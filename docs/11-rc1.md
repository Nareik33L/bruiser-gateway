# Bruiser Gateway — RC1

V1 stays feature-frozen. RC1 closes the independent security review.
The product promise is unchanged: **one customer, one execution.**

## Release notes

Production Candidate (RC1) hardens identity, origin authority, resource
identity, fencing, merchant execution budget, session revocation, replay,
authorize least privilege, rate limits, and the header trust boundary.
No commercial features were added.

### Closed findings

| ID | Finding | Closeout |
|----|---------|----------|
| C1 | Production identity | JWKS/OIDC with issuer, audience, expiry, merchant binding, rotation, fail-closed cache. HS256 only when `BRUISER_DEV_ASSERTIONS=1`. Production refuses that flag and requires JWKS/issuer/audience. |
| C2 | Origin authority | Origin verifies execution JWT + fence + merchant + resource + expiry + revoke via introspect. `/v1/authorize` no longer returns `X-Bruiser-Origin-Secret`. Edge/Proxy inject the secret from local config. Default origin secrets fail `config validate` in production. |
| H1 | Canonical resource | Case, whitespace, slash, punctuation, and duplicate separators fold to one domain key. Malformed IDs are rejected. |
| H2 | End-to-end fence | Downstream SDK + introspect reject stale fence, revoked, and handed-off executions. |
| H3 | Execution budget | Merchant policy `budget.max_ops` (and named aliases). One execution cannot exceed the configured cap. |
| M1 | Session revocation | `POST /v1/sessions/logout` and `/revoke`. Authenticated routes check the session store. Refresh issues a new token only for a live session. |
| M2 | Replay | `Idempotency-Key` / `X-Bruiser-Nonce` / client `X-Request-Id` recorded; duplicates return 409. |
| M3 | Secure authorize | Edge secret required. Response is execution material only. Every ALLOW is audited. |
| M4 | Rate limits | Configurable per sessions/acquire/renew/release/authorize and merchant/customer/principal/IP. `bruiser_rate_limited_total`. |
| M5 | Header trust | Inbound `X-Bruiser-*` stripped except edge/admin/event. Unsigned identity headers require a trusted edge. |
| L1 | Control surface | Revoke/handoff/JWKS/Embedded SDK exist. Admin RBAC remains a single admin secret in RC1 (documented; SSO is post-RC1). |
| L2 | Clock skew | 5s leeway on `exp` only. Fence comparison has no skew. |
| L3 | State terms | Decision: `ALLOW`/`BUSY`/`QUEUED`/`DENIED`. Execution: `ACTIVE`/`RELEASED`/`EXPIRED`/`REVOKED`/`HANDED_OFF`/`QUEUED`. Advertised on `/.well-known/bruiser/protocol`. |

## Authority Check

`bruiser authority-check --front <edge> --origin <origin> --control <bruiser>`
must be **PASS** before go-live. RC1 probes additionally cover resource
variants, forged execution, modified fence, and unsigned identity.

Lab: `make authority-check` against Compose.

## Configuration validation

`bruiser config validate` prints `PASS` / `FAIL` with an actionable field
for: default secrets, missing JWKS (production), invalid issuer/audience,
missing origin lockdown, unsafe unmatched routes, duplicate secrets,
invalid mode, development assertions in production.

Lab (non-production) against `configs/example.yaml` is PASS with WARN on
`unmatched: allow`. Production (`BRUISER_ENV=production`) FAILs that file
until JWKS/issuer/audience and generated secrets are set.

  `TestAuthorityCheckLockdownOnPass` / deployment acceptance

`make soak` on this revision (10,000 agents, 30 minutes,
renew/reconnect/release/queue, replica kill at 12m + replacement at
18m) stayed at **ACTIVE=1** throughout, **0 unexpected errors**,
`created=1`, queue at `max_waiters=8`. End: 3,458,509 requests,
p50 27.1ms / p99 50.6ms, heap 14–31MB, goroutines ~320–345 then 34
at stop.

Versus the V1 freeze soak (3,940,237 requests, 0 errors, p50 ≈ 30ms /
p99 ≈ 60ms, heap 14–34MB, goroutines ~340 then 34): throughput is
about 12% lower (LiveSession + keyed rate-limit checks on the hot
path). Latency, memory, goroutines, exclusivity, and replica recovery
are at or better than that baseline. Not a material health regression.
